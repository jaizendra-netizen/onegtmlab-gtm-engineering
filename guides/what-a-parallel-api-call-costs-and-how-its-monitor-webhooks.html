What a Parallel API call costs, and how its Monitor, webhooks and limits behave

If you plan to put a web research API inside an agent or an enrichment job, the sticker price is only part of the picture. You also need the cost of one call, how scheduled monitoring is billed, how results reach your code and where the rate limits bite. These notes come from Parallel's own pricing, docs and rate limit pages, verified on 25 Oct 2026. Check the vendor's own pricing page before you buy, because prices and limits change.

What one call costs

Parallel prices usage by the thousand. The cheapest items are Search in turbo or fast mode and Extract, at $1 per 1,000 requests or URLs. Search in basic or advanced mode is $5 per 1,000. We measured one fast search and one extracted URL at $0.001 each.

Two details change the arithmetic:

  • Search prices include 10 results, and each extra result costs $1 per 1,000. Asking for 50 results on basic or advanced is $0.045 per call, not $0.005.
  • The default Search mode is advanced at $5 per 1,000. Fast is $1, and the docs call it the right choice for most agents. Set the mode yourself.

Task, the structured research and enrichment product, is billed per successful run by processor: lite $5 per 1,000, base $10, core $25, core2x $50, pro $100, ultra $300, ultra2x $600, ultra4x $1,200 and ultra8x $2,400 (that is $2.40 a run). Failed runs are not billed. Price does not change with the number of fields, but each processor caps them: roughly 2 on lite, 5 on base and 10 on core.

How Monitor is billed

Monitor watches the web on a schedule and is billed per execution, meaning per check. Lite is $3 per 1,000 executions and base is $10 per 1,000. A core processor exists in the API, but the page shows no published price for it.

The page gives a handy example: an hourly lite monitor runs about 720 times a month, which is about $2.16. Budget the same way: monitors times checks per month times the per execution price.

A monitor is one of two types, an event stream built on a query or a snapshot built on a task output. You can list, update, cancel and trigger monitors, and read their events newest first. Monitor is generally available on /v1/monitors, though the rate limits page still names an older /v1alpha path, so trust the live API reference.

Webhooks: how results reach you

Polling works and is free of rate limits, but signals are better pushed into your own system. Webhooks exist for Task runs, FindAll runs and Monitor. Monitor sends three events: monitor.event.detected, monitor.execution.completed and monitor.execution.failed.

Deliveries follow the Standard Webhooks format, with webhook-id, webhook-timestamp and webhook-signature headers. The signature is HMAC v1, made with an account secret you create under Settings, then Webhooks. Verify it before you act on a payload. One caveat from the page: the Task webhook is not available through the Python SDK.

Rate limits to design around

Limits apply per product over a rolling 60 second window, and only POST requests that create resources count. GET requests and polling do not. A breach returns a 429, and no rate limit headers come back, only an x-request-id, so your client needs its own pacing and backoff.

The defaults we recorded:

  • Search, Image Search, Extract and Entity Search: 600 per minute each.
  • Tasks and Task Groups: 2,000 per minute, counted per run created.
  • Monitor creation: 300 per minute.
  • FindAll run creation: the sources disagree, 300 per hour on the docs page and 25 per hour on the pricing page. Plan for the lower number.

Task Groups take up to 1,000 runs per add runs request, and the balance is checked for the whole batch upfront.

Billing guardrails that surprise people

Monthly spend limits are notify only and never block requests. Pro and ultra tasks and whole Task Group batches reserve credit upfront, so a positive balance can still return a 402. And with a plain API key you cannot read your balance, because the Account API needs an OAuth access token.

New organisations got an $80 credit with no card in the live app, expiring about 60 days after signup. Confirm what applies to you.

What we saw in practice

We ran the Task API on the base processor for an AI workforce startup client, to find the top executive at each of 108 small companies. It returned a name for 76 and found nobody for 24. On a separate 181 contact research run, 14 Task runs did not finish within our polling window. Build in retries and a webhook or generous polling, not a single pass. The takeaway

Budget Parallel by the unit: set the Search mode yourself, count extra results and pick the cheapest Task processor that fits your field count. Cost Monitor as executions per month, use signed webhooks for pushes, pace your own calls because a 429 comes with no headers, and remember that spend limits warn but do not stop. Pilot on a small list first.
